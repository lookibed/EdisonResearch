# Учёный, который сам выбирает опыты

Добавлен экспериментальный режим `--scientist-mode llm`. Сталкер по-прежнему
находит сущности через локальный источник. Для каждой сущности новый учёный получает
только описание доступных действий и наблюдения над этой сущностью.

LLM формулирует вопрос, как минимум две конкурирующие гипотезы, прогнозы и условия
опровержения. Затем пишет Python-программу: выбирает входы, вызывает инструменты,
сравнивает результаты. Следующий раунд получает реальные ответы инструментов,
ошибки и предыдущую программу, чтобы изменить объяснение или поставить другой опыт.
После раундов выполняется отдельный обзор оставшихся вопросов.

Исследовательский цикл находится в `edison/investigator.py`, изолированный
исполнитель — в `edison/experiments.py`, связь со Сталкером — в
`edison/llm_scientist.py`. Генератор комбинаций сохраняет отдельный контекст:
исследовательские журналы и оценки ему не передаются. Агент-планировщик не добавлен.

## Что стало свободным и что осталось заданным

В новом режиме нет заранее выбранных входных примеров и перечня исследуемых
свойств. Вопросы, процедуры и анализ предлагает модель. Программист всё ещё задаёт
интерфейсы, доступные вмешательства, ограничения ресурсов и сами тестовые миры.
Система не умеет самостоятельно подключать произвольный физический прибор или
интернет-источник. Для новой среды нужен доверенный адаптер инструментов.

Точные запросы повторно не исполняются: ответ берётся из памяти в пределах того же
источника и его версии. Независимые шумовые пробы требуют другого `replicate`.
Сырые измерения записывает доверенный инструмент; вывод `emit` считается анализом
программы и не может создать запись измерения.

Интерпретации модели имеют статус `llm_interpretation_unverified`, ссылки на
существующие измерения, область действия и неопределённости. Они не становятся
подтверждёнными законами автоматически. Проверенные записи `observed_response`
утверждают только результат конкретного запроса. Независимая проверка прогнозов
на отложенных опытах пока не реализована. Эта версия не доказывает zero-shot
способность или универсальность учёного.

## Запуск

Нужны Linux x86_64, Python 3.10+, `bubblewrap`, разрешённые пользовательские
пространства имён и seccomp. Вложенная облачная песочница может запрещать запуск
`bubblewrap`, даже если пакет установлен. Предварительная проверка выполняется
до оплачиваемого запроса модели; при её провале исследование останавливается.
Исполнения кода модели напрямую на хосте нет.

Код опытов работает без сети, переменных с ключами и файлов проекта, с ограничениями
времени, памяти, числа вызовов и вывода. Создание процессов запрещено seccomp.
Модель вызывается родительским процессом через существующие `OPENROUTER_API_KEY`
и `EDISON_MODEL`; секреты в код опыта не передаются.

```bash
mkdir -p artifacts
python -m edison.pipeline --discover --scientist-mode llm --scientist-rounds 2 --scientist-tool-budget 24 --provider none --budget 96 > artifacts/llm-discovery.json
```

`--provider none` отключает генератор комбинаций, но учёный в режиме `llm`
продолжает обращаться к OpenRouter. На каждую изучаемую сущность: два раунда
плюс один обзор, то есть три API-запроса при корректных ответах. Каждая фаза
допускает одно дополнительное исправление формата (максимум шесть API-запросов
при двух раундах). Сетевые ошибки автоматически не повторяются.
Бюджет инструментов задаётся отдельно
для каждой сущности. По умолчанию сохраняется прежний режим `fixed`.

Для проверки переноса одного исследовательского цикла подготовлены три среды:
неизвестная функция списка чисел, битовый преобразователь и движение тела под
силой. Они имеют разные действия и скрытые законы; готовых опытов для модели нет.

```bash
python -m edison.lab --domain function --rounds 2 --tool-budget 24 > artifacts/research-function.json
python -m edison.lab --domain bits --rounds 2 --tool-budget 24 > artifacts/research-bits.json
python -m edison.lab --domain physics --rounds 2 --tool-budget 24 > artifacts/research-physics.json
```

Результаты запусков ниже; наличие измерений не означает доказательство закона.

## Контракт промптов v3

Общая инструкция задаёт роль исследователя и границу между измерением и
интерпретацией. Отдельные инструкции отвечают за постановку опыта и за обзор.
В контекст входят публичный интерфейс, оставшийся бюджет, измерения, ошибки и
предыдущие опыты. Не входят скрытый закон, seed и результаты поиска комбинаций.
Примеров решений или готового списка проверяемых свойств нет.

Схема ответа теперь передаётся в API через `response_format: json_schema` с
`strict: true`; маршрутизация требует поддержки параметров. Режим не откатывается
молча к произвольному JSON, если модель или провайдер схему не поддерживает.
Локальная проверка остаётся обязательной: схема не доказывает корректность кода,
существование ссылок на измерения или истинность объяснения.

До исполнения проверяется синтаксис Python (разбор AST без запуска). При ошибке
схемы, ссылок или синтаксиса модель получает отвергнутый ответ и диагностику,
после чего может один раз прислать полный исправленный объект. Все попытки,
ответы и возвращённое API использование токенов сохраняются в `model_attempts`.
Ошибка времени исполнения становится обратной связью следующего раунда.

Температура учёного снижена с 0.8 до 0.2 для предсказуемости формата. Это рабочая
настройка, а не доказанный оптимум исследовательского качества. Промпт требует
конкурирующих объяснений и контрпримеров, но не гарантирует непредвзятость LLM.
Генератор комбинаций сохраняет прежние инструкции и температуру.

Учёному теперь выделяется до 8192 выходных токенов вместо 4096; генератору
комбинаций остаётся 4096. Это увеличивает возможный расход на запрос и не
гарантирует отсутствие обрывов. Промпт требует коротких выводов и выборочных
ссылок вместо повторения таблицы данных. Лимиты уникальных опытов и всех
вызовов программы передаются отдельно в `execution_limits`: повторный запрос
не создаёт нового измерения, но расходует лимит вызовов программы.

## Проверка этой версии

Последний обычный прогон: `python -m unittest discover -s tests -q` — 51 пройденный,
7 пропущенных тестов, ошибок нет. Пропущены проверки реального изолированного
исполнения: RPC, ограничения ресурсов, недоступность ключей/сети/проекта,
защита журнала измерений, обратная связь и загрузка прежних наблюдений.

Полный прогон на хосте с поддержкой изоляции:

```bash
EDISON_TEST_SANDBOX=1 python -m unittest discover -s tests -v
```

Внутри внешней облачной песочницы предварительная проверка завершилась
`SandboxUnavailable`. После разрешённого запуска вне неё полный набор из
56 тестов прошёл без пропусков, включая семь проверок реального исполнителя.
После добавления диагностики обрыва и двух регрессионных проверок обычный
прогон содержит 58 тестов; повтор полной изоляции был прерван на запросе
разрешения. Исполнитель изоляции в этих изменениях не менялся.

Первое живое исследование функции через OpenRouter завершилось без наблюдений:
оба ответа содержали описание опыта вместо исполнимого Python и дали SyntaxError.
Обзор не выдавал несуществующие измерения за знания. Полный журнал сохранён в
`reports/research-function-first-attempt.json`. После этого контракт запроса уточнён:
поле experiment должно содержать только код, ответы инструментов — словари.
Живой повтор со строгой схемой выполнен на всех трёх средах:

| Среда | Измерения | Выполнение | Обзор |
| --- | ---: | --- | --- |
| function | 10 | Первый раунд успешен; во втором RuntimeError без сохранённой точной причины | Успешен: предложена сумма квадратов, с оговоркой конечной выборки |
| bits | 14 | Первый раунд превысил 24 вызова (22 уникальных попытки, включая 8 ошибок инструмента, и 2 повтора); второй ответ оборван по токенам | Ответ оборван по токенам |
| physics | 20 | Оба раунда успешны | Ответ оборван по токенам |

Исходные журналы: `reports/research-function-structured.json`,
`reports/research-bits-structured.json`, `reports/research-physics-structured.json`.
Три обрыва диагностированы по `finish_reason=length`, а не по догадке о JSON.
Точную причину ошибки второго раунда функции восстановить нельзя: тогда
сохранялось только имя исключения. Теперь безопасная диагностика транспорта
и расход токенов при обрыве сохраняются в `model_attempts`.

Совместное изменение схемы и промптов
дало исполнимые опыты; вклад каждого изменения отдельно и оптимальность
промптинга не установлены. Zero-shot перенос и истинность обобщений не доказаны.

## Живой повтор v3

Запуск на версии кода `77b7cc9`, по два раунда и обзор на среду, бюджет
24 уникальных попытки. Один и тот же контракт, без изменения промпта между
средами. Всего 9 API-запросов, возвращённое API использование — 63967 токенов,
включая вход, выход и ответы, оборванные лимитом.

| Среда | Измерения | Первый раунд | Второй раунд | Обзор |
| --- | ---: | --- | --- | --- |
| function | 12 | Успешен | Обрыв на 8192 токенах | Успешен |
| bits | 16 | Успешен | Успешен | Успешен |
| physics | 10 | Успешен | Обрыв на 8192 токенах | Успешен |

Все 38 исходных ответов воспроизведены вызовом соответствующих инструментов
с записанными аргументами. Это проверка воспроизводимости измерений, а не
независимая проверка интерпретаций. Ошибок исполнения Python, превышений
бюджета вызовов и исправлений формата в этом запуске не было. Неподходящие
входы декодера дали четыре ошибки инструмента; это отдельный результат пробы,
а не ошибка исполнения программы.

Обзор функции предположил сумму квадратов; обзор битового преобразователя —
блоки 4→7, дополнение нулями и исправление одного проверенного повреждения;
обзор физики — линейную реакцию на силу и движение с вязким сопротивлением.
Все эти объяснения сохраняют статус `llm_interpretation_unverified`.

Журналы: `reports/research-function-v3.json`, `reports/research-bits-v3.json`,
`reports/research-physics-v3.json`; сводка — `reports/research-v3-summary.json`.
Вывод проверки: увеличение лимита до 8192 не устранило обрывы. По сохранённым
данным нельзя разделить расход на внутреннее рассуждение и видимый ответ;
не следует приписывать обрыв только многословию текста. Следующий шаг требует
диагностики этой разбивки и сокращения контракта повторного раунда, а не
очередного необоснованного увеличения лимита.
