# Сталкер с сохраняемым графом

Экспериментальная реализация: `edison.structural_graph` и `edison.structural_trial`.
Работает на статических источниках v2; прежний каталог битовых компонентов и
генератор комбинаций остаются отдельными подсистемами. Новая сущность в графе
сама по себе не получает исполнимых возможностей.

## Что происходит на каждом ходе

```text
публичный ввод + прошлые ответы + собственная память
    → LLM: graph_delta и следующий вопрос/действие
    → атомарная проверка структуры, ID, состояний и ссылок
    → сохранение изменения графа
    → доверенный инструмент: новый исходный ответ с call_id
    → следующий ход, который сможет интерпретировать этот ответ
```

На последнем ходе окна есть отдельное сохранение без инструментов: последний
ответ не теряется из-за исчерпания бюджета. Пустое изменение допустимо. Модель
не обязана находить новую сущность после каждого измерения.

В графе отдельно хранятся сущности, определения отношений, утверждения, вопросы,
изменения статусов вопросов и состояния. Термины отношений и уровни разбиения
выбирает модель. Количество частей, состав и готовое дерево кабеля не заданы.

ID неизменяемы. Новое знание о старой сущности записывается новым утверждением.
Исправление может сослаться на прежнее через `supersedes`; прежняя запись и её
основания сохраняются. Альтернативные разбиения и противоречивые сообщения могут
сосуществовать. Автоматического склеивания сущностей по похожему названию нет.

Утверждение содержит участников с ролями, происхождение, область действия,
состояния и свидетельства. Проверка не позволяет ссылаться на ещё не полученный
ответ или состояние. Одного документа/отказа доступа недостаточно для статуса
прямого наблюдения. Это **проверка протокола, а не истинности интерпретации**:
смысл вывода, достаточность свидетельств и честность области действия требуют
отдельной проверки. Ссылка START тоже не удостоверяет произвольное утверждение.

## Вопросы и широта

Модель добавляет вопросы и их ответвления. На каждом втором действии выделяется
слот старейшему открытому вопросу; остальные слоты модель распределяет сама.
Корневой вопрос всей задачи служит запасным, когда других открытых вопросов нет.
Очередь задаёт очередность обслуживания уже зарегистрированных вопросов, не
объявляет физические направления возможными или невозможными.

`answered` и `blocked` — записанные решения модели. Они не удаляют вопрос и не
доказывают полноту его исследования; вопрос можно открыть снова. FIFO не
гарантирует обнаружение всех возможных вопросов. В конечном запуске никакой
безграничности покрытия не доказано. Генератор комбинаций не получает этот граф,
измерения и оценки; автоматического моста в него здесь ещё нет.

## Воспроизводимый запуск

```bash
python -m unittest discover -s tests -v
python -m edison.structural_trial --memory graph --output artifacts/new-graph-run
python -m edison.structural_trial --memory registry --output artifacts/new-registry-run
python -m edison.structural_trial --fixture fixtures/structural_stalker/homogeneous_v2 --output artifacts/new-control-run
```

Используются уже настроенные `OPENROUTER_API_KEY` и `EDISON_MODEL`. API требует
строгий JSON Schema; неподдерживаемый формат не заменяется молча свободным JSON.
Диспетчер не исполняет сгенерированный код. Нужен доступ к OpenRouter, bubblewrap
для этого исследователя не требуется.

Папка результата должна быть новой. `session.json` сохраняет точные исходящие
пакеты, ответы, ошибки и расход токенов; `graph.json` — текущее состояние;
`base-graph.json` и `base-report.json` замораживаются до открытия нового источника.
`new_source-*` сохраняют второй этап. Граф можно восстановить по журналу принятых
изменений; исходные ответы остаются в журнале и доступны модели целиком.

## Сравнение памяти

Два режима используют одинаковый системный промпт, схему ответа, инструменты,
температуру, предел вывода и бюджеты. `graph` получает весь накопленный граф;
`registry` получает описания сущностей, определения отношений, вопросы/статусы,
состояния и ID утверждений, но не их накопленные тексты и основания. Оба видят
полную историю исходных ответов. Выходные изменения обоих режимов сохраняются.

Это абляция обратной связи утверждений, а не сравнение «LLM против кода» и не
сравнение со старым промптом v1. Контекст и расход токенов различаются по самой
конструкции опыта. Один запуск каждого режима не устанавливает причинного
преимущества: нужны повторы и смысловая оценка без знания режима.

Первые попытки v2 и v2.1 выявили повторную отправку снимка вместо изменений,
изменение старых ID и переполнение вывода. В v2.1 обеим сторонам одинаково уточнено:
только новые записи, не более 4 сущностей и 5 утверждений за ход. В v2.2 исправлено
обращение к исходному измерению через `call_id`; обязательный вопрос и `finish`
задаются JSON Schema, а отклонённый кандидат возвращается модели с диагностикой.
На основное окно разрешены 4 ошибочных ответа плюс завершающее сохранение, на второе — 2.
Предел инструментов остался 18 + 3, вывода — 6144 токена на обращение.
Исчерпание ошибок отмечается `partial`, даже если последняя запись сохранена.
Неудачные попытки сохраняются; после просмотра результата эталонные критерии не переписываются.

Восстановить граф без ключа и сети:

```python
import json
from pathlib import Path
from edison.structural_trial import replay_session

log = json.loads(Path('artifacts/new-graph-run/session.json').read_text())
restored = replay_session(log)
```

Аудит повторяет **все** инструментальные ответы и изменения графа, проверяет хеши
фикстуры и снимок до нового источника:

```bash
python scripts/audit_structural_trials.py artifacts/new-graph-run --fixture fixtures/structural_stalker/cable_v2
```
